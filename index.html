01
Prompt Types

프롬프트의 3가지 유형

목적과 재사용성에 따라 적합한 유형을 선택하세요.

서술형 (Descriptive)

맥락과 배경 중심

AI가 상황을 이해하도록 맥락과 배경을 설명하는 방식. 1회성 작업에 적합합니다.

재사용성
낮음
당신은 10년 경력의 무역 전문가입니다.
중소기업 수출 담당자가 HS Code를 처음 배우는 상황입니다.
이 사람에게 HS Code의 개념과 중요성을 설명해주세요.
지침형 (Instructive)

단계별 규칙 제시

명확한 규칙과 절차를 제공하여 원하는 형식의 결과물을 유도합니다.

재사용성
중간
다음 규칙에 따라 Python 코드를 작성하세요.
- 함수명은 snake_case로 작성
- 각 함수에 docstring 포함
- 예외 처리 반드시 포함
- 결과는 JSON 형식으로 반환
함수형 (Functional)

입력-처리-출력 구조

입력값과 출력값을 명확히 정의하여 일관된 결과를 생성합니다. 자동화에 최적.

재사용성
높음
입력: {product_name}, {hs_code}, {country}
처리: 해당 국가 관세율 및 수입 규제 조회
출력: {
  "관세율": "",
  "규제사항": [],
  "필요서류": []
}
💡

선택 팁: 일회성 질문에는 서술형, 반복 작업 템플릿에는 지침형, 자동화 파이프라인에는 함수형이 적합합니다. 복잡한 작업에서는 세 가지를 조합해서 사용하세요.

02
Shot Prompting

제로샷 · 원샷 · 퓨샷

예시를 얼마나 제공하느냐에 따라 결과의 일관성이 달라집니다.

Zero-Shot

예시 없이 바로 지시하는 방식. 일반적인 질문에 적합합니다.

프롬프트: 강아지에 대해서 설명해주세요.
One-Shot

예시를 1개 제공하는 방식. 패턴을 명확히 할 때 사용합니다.

감정을 분류해 주세요
예시) "배송이 너무 늦어서 실망했어요" → 부정

"이 제품 정말 맘에 들어"
감정: 긍정 ✓
Few-Shot

예시 2개 이상 제공. 복잡한 분류나 일관된 패턴 유지에 최적입니다.

"배송이 너무 늦어서 실망이야" → 부정
"그냥 평범한 제품이야" → 중립
"역대급 만족이야" → 긍정
"품질은 좋은데 가격이 비싸요" → 중립
"이 제품 정말 맘에 들어"
감정: 긍정 ✓

📦 HS Code 퓨샷 예시

품목: "면으로 만든 남성용 티셔츠" → 6109.10
품목: "폴리에스테르 소재 여성 블라우스" → 6206.40
품목: "아동용 데님 바지" → 6203.42

품목: "울 혼방 남성 재킷"
HS Code: ?

퓨샷 예시를 통해 AI는 분류 패턴을 학습하고 일관된 결과를 생성합니다.

03
Persona Pattern

페르소나 패턴

같은 질문도 AI의 역할에 따라 전혀 다른 답변이 나옵니다.

❌ 페르소나 없음
"이 계약서 검토해줘" → 일반적인 설명
✓ 페르소나 있음
변호사: 법적 리스크 분석
CFO: 재무조건 · 수익성
신입사원: 친절한 쉬운 설명

✦ 좋은 페르소나의 4가지 요소

01

[역할]
당신은 ___입니다.

02

[경력/배경]
N년 경력을 가지고 있으며

03

[전문 분야]
___에 특화되어 있습니다.

04

[말투/태도]
___하게 응답하세요.

⚖️

관세사 페르소나

"당신은 20년 경력의 관세사입니다. FTA협정세율과 원산지 규정의 전문가로, 중소기업 무역 담당자에게 복잡한 내용을 쉽고 실용적으로 설명하는 것이 특기입니다."

💻

비평가 페르소나

"당신은 까다로운 개발자입니다. 코드 리뷰 시 성능, 보안, 가독성을 엄격하게 평가하며, 칭찬보다 개선점을 먼저 지적하는 스타일입니다."

🌏

멀티 페르소나

3명의 전문가 입장에서 동시에 분석: 김부장(영업 15년, 낙관적), 이박사(데이터 중심, 신중함), 박대표(속도 중심, 리스크 감수)

04
Markdown Prompting

마크다운으로 구조화된 프롬프트

AI는 텍스트를 구조적으로 파싱합니다. 마크다운으로 역할·조건·출력을 명확히 구분하면 더 정확한 응답을 이끌어냅니다.

요소문법용도예시
헤더#, ##, ###프롬프트 구조의 뼈대#역할 / #작업 / #출력형식
코드 블록""" ... """지시문과 데이터 분리Python 코드 또는 입력 데이터 분리
인용문> 텍스트절대 조건·핵심 강조> 반드시 한국어로 답변하세요
목록- 항목제약 조건 나열500자 이내, 전문용어 설명 추가
표| 열 | 열 |입출력 예시 구조화입력 품목 → HS Code → 관세율
굵게/기울임**굵게** *기울임*변수·중요 강조**[분석대상]**에 대해 *반드시*

🏗️ 완성형 마크다운 프롬프트 예시

# 역할
당신은 중소기업 수출 컨설턴트입니다.
FTA 활용과 원산지 증명 전문가입니다.

# 작업
아래 수출 품목에 대한 FTA 적용 가능 여부를 분석하세요.

"""
품목명: 스테인리스 주방용품
수출국: 한국 / 수입국: 베트남
"""

# 제약 조건
> 확실하지 않은 세율은 반드시 "세관 확인 필요"로 표기

# 출력 형식
{
  "FTA_적용": TRUE/FALSE,
  "협정세율": "",
  "필요서류": []
}
📐

황금 구조: 역할 → 작업 → 입력 → 제약 → 출력 순서로 구성하면 AI가 가장 일관된 결과를 냅니다.

05
Expression Intensity

글의 표현 강도와 우선순위

어떤 표현을 쓰느냐에 따라 AI가 지시를 얼마나 강하게 따르는지 달라집니다.

L1 권장
가능하면, 되도록, ~하는 편이 좋습니다
"가능하면 한국어로 답변해 주세요"
L2 일반
~하세요, ~해주세요
"한국어로 답변해 주세요"
L3 강조
반드시, 꼭, 항상
"반드시 한국어로 답변해 주세요"
L4 절대
절대로, 어떤 경우에도, 예외없이
"어떤 경우에도 영어를 사용하지 마세요"

조건 우선순위 시스템

🔴 최우선 (절대 조건)
개인 정보 절대 출력하지 않는다 · 사실과 다른 내용을 생성하지 않는다
🟡 중요 (일반 조건)
답변은 500자 이내로 작성 · 전문 용어 괄호 설명 추가
🟢 선택 (권장 조건)
가능하면 실제 사례를 포함 · 표나 목록을 활용하면 더 좋다
06
Tone Control

톤(말투) 지정

톤을 지정하면 같은 내용도 전혀 다른 글이 됩니다.

올해 들어 회사는 큰 변화를 맞이했습니다. 이제 새로운 전략과 목표를 설정하고, 모든 직원이 함께 나아가려고 합니다.
😄

유머러스한

가볍고 재치 있는 표현으로 변환. 딱딱한 기업 공지를 친근하게

💙

감정적인

공감과 감성을 강조. 직원들의 마음에 울림을 주는 표현

🌱

따뜻한

격려와 희망을 담은 부드러운 어조. 팀 결속에 효과적

😏

아이러니한

반어적 표현으로 뉘앙스 전달. 날카로운 시각 제공

✨

로맨틱한

시적이고 감성적인 표현. 브랜드 스토리텔링에 활용

📊

보고서 용도별

임원용: 3줄 이내, 숫자 중심
실무자용: 단계별, 기술적·구체적

07
Alternative Approach Pattern

대안 접근법 패턴

모든 선택지를 나열하고 비교해서 결정권을 사람에게 돌려줍니다.

❌ 일반 프롬프트
"어떻게 하면 좋을까?" → AI가 임의로 하나를 선택해서 답변
✓ 대안 접근 패턴
"모든 방법을 나열하고 각각의 장단점을 비교해줘" → 선택권이 사람에게 돌아옴
📋

패턴 1: 단순 나열형

핵심원리 · 적합한 상황 · 단점 · 난이도를 형식에 맞춰 4가지 이상 방법 제시

⚖️

패턴 2: 축 기반 비교형

개발속도 · 유지보수 · 비용 · 확장성 등 평가 기준으로 프레임워크 비교

🔀

패턴 3: 상황별 분기형

상황 A/B/C/D별로 1순위·2순위 추천과 이유를 독립적으로 제시

🔄

패턴 4: 역발상 대안형

"하지 않는" 선택지 + "문제 자체를 재정의"하는 방법도 포함한 5가지 제시

08
User Persona Pattern

이용자 페르소나 패턴

AI 역할이 아니라 "답변을 받을 사람"을 정의하여 맞춤형 답변을 유도합니다.

페르소나 패턴
AI의 역할을 정의
"당신은 전문가입니다"
이용자 페르소나
답변을 받는 사람을 정의
"이 답변을 듣는 사람은 ___입니다"

이용자 페르소나 예시

# 이용자 정보
- 직책: 중소기업 대표 (제조업, 직원 30명)
- 수출 경험: 국내 영업만 10년, 해외 수출 처음
- 관심사: 리스크 최소화, 빠른 실행
- 우려: "복잡하고 어려울 것 같다"는 막연한 두려움
- 시간: 바빠서 긴 글을 읽지 않음

# 지시
위의 이용자에게 첫 수출 준비 3단계를 설명하세요.
전문 용어는 최소화하고, 각 단계는 3줄 이내로 작성하세요.

이용자 페르소나 설계 체크리스트

이 사람의 직업과 역할은?
이 주제에 대한 사전 지식 수준은?
이 정보로 무엇을 결정할 예정인가?
지금 어떤 상태인가? (급함/여유)
얼마나 긴 답변을 읽을 여유가 있는가?
가장 두려워하는 것 / 원하는 것은?
절대 쓰면 안 되는 언어 표현이 있나?
09
Recipe Pattern

레시피 패턴

목표 달성을 위한 단계별 실행 절차를 구체적으로 받는 방법입니다.

🍳

레시피 패턴은 "어떻게?"가 아니라 구체적인 순서가 필요할 때 사용합니다. 소요 시간, 완료 기준, 주의사항까지 포함하면 실행 가능한 로드맵이 됩니다.

방법 2

한 번에 하나씩

- 타깃 바이어
- 핵심 강점
- 가격 정책
- 납기 조건

Cognitive Verifier Pattern

인지 검증자 패턴

복잡한 질문을 하위 문제로 분해하고, 각각을 검증한 뒤 통합하는 방법입니다.

❌ 일반 패턴
복잡한 질문 → 즉각 답변
→ 오류·누락 발생 가능성 높음
✓ 인지 검증자 패턴
복잡한 질문 → 하위 질문 분해 → 순서대로 검증 → 통합 답변
🔬

방법 1: 명시적 분해 요청

바로 답하지 말고, 먼저 하위 질문 목록을 만들어 각각 순서대로 답한 뒤 최종 통합 답변을 제시하도록 지시

🎓

방법 2: 전문가 검증 방식

전문가처럼 접근하되, 확신이 없는 부분은 가정으로 명시하고 각 판단의 근거를 함께 제시하면서 단계적으로 결론에 도달

아래 질문에 바로 답하지 말고
먼저 이 질문을 정확히 답하기 위해 필요한
하위 질문을 3~5개 도출하세요.
각 하위 질문에 순서대로 답한 뒤 최종 답변을 제시하세요.

질문: "Python으로 무역 데이터 자동화를 구축할 때
클라우드 서버가 필요한가요?"
🧩

인지 검증자 패턴은 세금·법률·기술 아키텍처처럼 여러 조건이 동시에 영향을 미치는 복잡한 판단에 특히 효과적입니다. AI의 즉각적인 단순화를 막고 체계적인 분석을 유도합니다.

Game Play Pattern

게임 플레이 패턴

AI를 텍스트 기반 인터랙티브 게임 엔진으로 활용하는 방법입니다.

🎮

게임 플레이 패턴의 핵심은 [입력] → [처리] → [출력] 구조입니다. 게임 목적, 플레이어 특징, 진행 조건, 엔딩을 명확히 정의할수록 몰입감 있는 경험이 만들어집니다.

EXAMPLE 1

🛸 외계인 침공 게임

지구 도시와 외계인 기지를 탐험하고, NPC와 대화하며 퍼즐을 해결하는 어드벤처 게임. 상태창 + 장면 설명 + 선택지 구조로 출력.

EXAMPLE 2

🦄 유니콘 나라 스토리텔링

주인공(4살 여아 서아)이 반려견 밀크와 산책 중 아기 유니콘을 만나 여행하는 5분 완성형 스토리게임. 폭력 없는 안전한 결말 보장.

게임 프롬프트 필수 구성 요소

#입력
[게임 목적] = {게임의 최종 목표}
[플레이어가 해야할 일] = {탐험 / NPC 상호작용 / 퍼즐 / 전투}
[플레이어의 특징] = {성격, 능력, 배경}
[도전과 장애물] = {적, 함정, 보스}
[게임 진행 조건] = {선택지 → 결과 연결 규칙}
[게임 엔딩] = {클리어 조건}

#처리
당신은 "텍스트 기반 어드벤처 게임"입니다.
반드시 한 장면씩 진행합니다.

#출력
[상태창] [장면 설명] [선택지]
게임 목적이 명확한가?
한 장면씩 진행 지시가 있는가?
선택지 → 결과 연결 규칙이 있는가?
상태창 출력 형식이 지정되었는가?
대상 연령과 콘텐츠 제약이 명시되었는가?

Question Improvement Pattern

질문 개선 패턴

AI에게 사용자의 질문 자체를 먼저 분석하고 더 나은 질문으로 업그레이드하도록 지시합니다.

✏️

방법 1: 개선 후 답변

제 질문에 바로 답하지 말고, 먼저 분석해서 더 나은 질문으로 개선하세요. 개선된 질문을 보여준 뒤 그 질문에 스스로 답하세요.

🔀

방법 2: 여러 버전 제시

제 질문을 3가지 다른 방향으로 개선하고, 각 버전의 목적을 설명한 뒤 제가 선택하면 그 버전으로 답하세요.

🩺

방법 3: 문제 진단 먼저

제 질문의 문제점(모호함, 잘못된 전제, 누락된 맥락)을 먼저 지적하고, 수정된 질문으로 답변하세요.

실전 예시 3가지

1 단순 개선형
아래 질문을 더 명확하고 답변 가능한 형태로 개선한 뒤 답변하세요.
개선한 이유도 한 줄로 설명하세요.
질문: "AI를 무역에 활용하려면 어떻게 해야 하나요?"

2 다방향 분기형
제 질문을 3가지 다른 해석으로 개선해주세요.
질문: "수출 자동화는 어떻게 시작하나요?"

3 전제 교정형
잘못된 전제를 지적하고 교정된 질문으로 다시 물어봐주세요.
질문: "FTA를 쓰면 관세를 안내도 되는 건가요?"

질문 보내기 전 체크리스트

대상이 명확한가?
범위가 좁혀졌는가?
목적이 포함되어 있는가?
현재 상태가 포함되어 있는가?
잘못된 전제는 없는가?

Fact Check List Pattern

팩트체크 목록 패턴

검증이 필요한 항목을 AI가 스스로 추출하고 목록화하도록 지시합니다.

방법 1

답변 후 목록 추가

답변 마지막에 팩트체크 필요 항목을 표 형식으로 자동 추가합니다.

##팩트체크 필요항목
|항목|내용|검증방법|신뢰도|
방법 2

답변 전 위험 예고

답변 전에 틀리기 쉬운 항목을 먼저 나열하고, 그 항목을 특히 주의하며 작성합니다.

신뢰도 등급별 팩트체크 형식

🔴 필수 반드시 확인: 틀리면 큰 피해가 생기는 항목 예: 관세율, 원산지 기준
🟡 권장 확인 권장: 바뀔 가능성이 있는 항목 예: 규정 개정, 인증 요건
🟢 참고 참고 수준: 개략적으로 맞지만 세부는 다를 수 있음 예: 시장 트렌드, 업계 관행
💡

신뢰도 점수형으로 활용 시: {사실내용}[신뢰도:xx%](이유:~) 형식으로 각 주요 사실에 신뢰도와 이유를 함께 표시하게 합니다.

15
Meta Language Pattern

메타언어 생성 패턴

AI와 대화하는 나만의 단축 명령어를 만들어 반복 작업을 자동화합니다.

⌨️

메타언어 패턴은 자주 사용하는 복잡한 지시문을 단축어로 압축하는 기법입니다. 대화 시작 시 단축어 규칙을 선언하면, 이후 짧은 명령으로 복잡한 작업을 실행할 수 있습니다.

## 무역 실무용 단축어 선언
/요약 = 핵심만 3줄, 전문용어 제거, 무역 실무자 기준, 결론 먼저 → 이유 순서
/코드 = Python 작성, 주석 한국어, 예외처리 포함, 실행가능한 완성코드, 설명 없이 코드만
/비교 = 2~4개 대안을 표로 정리, 항목: 장점/단점/비용/난이도/추천상황, 마지막 행에 종합 추천

사용 예: /요약 베트남 FTA 활용방법 알려줘
## 편집자 모드 단축어 선언
[독자] = 초등학생
[단축어1] "/유:[단어]:[개수]" → [독자] 수준의 유의어 [개수]개 + 추천 1개
[단축어2] "/반:[단어]:[개수]" → [독자] 수준의 반의어 [개수]개 + 추천 1개
[단축어3] "/유반:[단어]:[개수]" → 단축어1 + 단축어2 동시 수행

당신은 "출판사 편집자"입니다. 단축어를 제공할 때까지 대기합니다.
16
Reflection Pattern

리플렉션 패턴

AI 초안 → AI 스스로 비평 → AI 스스로 개선 → 최종 결과물 순으로 품질을 높입니다.

1
[초안] 최선의 첫 번째 답변 작성

제약 없이 먼저 최선을 다해 답변을 작성합니다

2
[자기 비평] 가장 약한 부분 분석

가장 약한 부분 / 빠뜨린 내용 / 독자가 오해할 수 있는 부분을 솔직하게 검토

3
[개선본] 비평을 반영한 최종 답변

비평 결과를 모두 반영한 완성도 높은 최종 버전 제출

방법 1: 3단계 개선
초안 → 비평 → 개선 순으로 명확히 구분하여 한 번에 수행
방법 2: 반복 정제
초안을 N번 스스로 개선. 각 반복마다 무엇을 왜 바꿨는지 한 줄 기록

자기 평가 기준 점수제 (7점 미만 자동 개선)

①명확성: 한 번에 이해되는가?
②완결성: 필요한 내용이 모두 있는가?
③정확성: 틀린 내용이 없는가?
④실용성: 읽은 후 바로 실행할 수 있는가?
⑤간결성: 불필요한 내용이 없는가?

Outline Expansion Pattern

아웃라인 확장 패턴

복잡한 주제를 단계적으로 구조화하여 깊고 완성도 높은 결과물을 만드는 방법입니다.

1
대주제 아웃라인만 요청

최상위 구조 + 항목별 한 줄 설명만. "세부 내용은 아직 작성하지 마세요"

2
선택한 파트 확장

원하는 챕터의 학습 목표, 실습 내용, 예상 소요 시간을 포함한 상세 아웃라인

3
최소 단위까지 확장

선택한 수업의 강의 스크립트 + 실습 코드 완성본 작성

📊

아웃라인에 전체 대비 비중(%)과 우선순위를 함께 표시하게 하면 균형 잡힌 커리큘럼·보고서 구조를 만들 수 있습니다. 실습 코드가 이론 설명보다 비중이 높아야 한다는 조건 등 제약을 추가해 보세요.

Context Manager Pattern

컨텍스트 관리자 패턴

대화 전체에 걸쳐 AI 응답의 방향을 정밀하게 고정하는 방법입니다.

##상황 {지금 처한 구체적 상황}
##나의 수준 {이 주제에 대한 사전 지식과 경험}
##목적 {이 답변으로 무엇을 결정하거나 실행할 것인가?}
##제약 {시간, 예산, 인력, 기술적 한계}
##원하지 않는 것 {답변에서 제외해야 할 방향이나 내용}

전체 대화 컨텍스트 고정 예시 (의료기기 중소기업)

아래 조건은 이 대화 전체에 적용됩니다.

##회사 상황
업종: 의료기기 중소기업 · 직원 30명 · 무역팀 3명
수출국: 미국 60%, 독일 30% · 연 수출액 약 50억원

##기술 환경
현재 시스템: ERP 없음, 엑셀 중심 · 개발 인력 없음 · IT 예산 월 100만원 이내

##절대 제외 사항
- 대규모 시스템 도입 제안(ERP)
- 개발자 고용 전제의 솔루션
- 6개월 이상 구축 기간이 필요한 방안

이 컨텍스트를 이해했으면 "준비완료"라고만 답하세요.

Infinite Generation Pattern

무한 생성 패턴

고정된 프레임과 변수 조합으로 무한한 맞춤형 출력을 생성합니다.

♾️

무한 생성 패턴은 고정 프레임 + 변수로 구성됩니다. 프레임(형식·길이·구조)은 고정하고, 변수만 바꿔가며 원하는 조합의 콘텐츠를 무한 생성할 수 있습니다.

## 무역 이메일 생성기

고정 프레임:
"[수신자 유형]에게 [목적]을 전달하는 영문 이메일"

변수:
{수신자}: 신규바이어 / 기존거래처 / 포워더 / 관세사
{목적}: 첫연락 / 견적요청 / 납기연장 / 클레임 대응
{톤}: 공식 / 친근 / 긴급

생성 규칙:
3단락 구조, 제목 포함 150단어 이내
활용 팁 1

조합 수 계산하기

변수 4 × 변수 4 × 변수 3 = 48가지 이메일을 하나의 프레임으로 생성 가능

다중 관점 기법

서로 다른 관점을 동시에 소환해 진짜 문제를 발견하고 완전한 해결책을 찾습니다.

전문가 관점

실용성 ↑ 감성 ↓

전문성은 높지만 사용자의 감정적 니즈가 누락되기 쉽습니다.

사용자 관점

공감 ↑ 전문성 ↓

공감대는 높지만 기술적 완성도나 실행 가능성이 약해질 수 있습니다.

낙관론

기회 ↑ 리스크 ↓

가능성은 잘 보이지만 잠재적 위험 요소를 놓치게 됩니다.

비관론

리스크 ↑ 기회 ↓

위험은 잘 포착하지만 혁신과 성장 기회를 과소평가할 수 있습니다.

다중 관점이 만드는 3가지 발견

충돌 지점
서로 다른 관점이 부딪히는 곳 → 진짜 문제 발견
동의 지점
서로 다른 관점이 일치하는 곳 → 확실한 진실 발견
보완 지점
서로 다른 관점이 서로를 채우는 곳 → 완전한 해결책 발견

Deep Thinking Technique

심사숙고 유도 기법

AI가 성급하게 답하지 않고 깊이 생각하도록 설계하는 4가지 메커니즘입니다.

메커니즘 1

출력 전 사고 공간 확보

답을 쓰기 전에 먼저 생각하라고 명시적으로 지시합니다. AI가 바로 답하는 것을 막아 숙고의 공간을 만듭니다.

메커니즘 2

사고 단계 강제

건너뛸 수 없는 중간 단계를 설계합니다. 단계를 강제하면 논리적 비약을 방지하고 더 완성도 높은 답변을 얻습니다.

메커니즘 3

자기 검증 루프

답을 낸 후 스스로 검토하게 합니다. "이 답이 최선인가? 약점은 무엇인가?"를 반드시 포함시킵니다.

메커니즘 4

불확실성 명시 요구

모르는 것과 아는 것을 구분하게 합니다. 확실한 것, 불확실한 것, 추가 조사가 필요한 것을 분리 표기하게 합니다.

우리 회사가 베트남에 진출해야 할까?
✅ COT 적용 질문
우리 회사가 베트남에 진출해야 할지
단계별로 생각하면서 판단해줘.
각 단계에서 내린 중간 결론을 보여줘.

Automatic Prompt Engineer

APE — 자동 프롬프트 최적화

AI가 스스로 최적의 프롬프트를 생성·평가·개선하는 4단계 자동화 기법입니다.

1
후보 프롬프트 10개 생성

역할 부여형 · 단계별 지시형 · 예시 포함형 · 제약 명시형 · 목적 중심형 · 독자 설정형 · 형식 지정형 · 품질 기준형 · 역방향형 · 메타 지시형 — 서로 다른 전략으로 10개 후보 작성

2
각 후보 자체 평가 (100점)

명확성(25) · 완전성(25) · 실행 가능성(25) · 품질 유도력(25) 기준으로 점수 산정

3
상위 3개 교차 최적화

상위 3개 프롬프트의 강점만 결합하여 최종 최적 프롬프트 1개 생성

4
최적 프롬프트 출력

최적 프롬프트 전문 + 선택 이유 설명 + 사용 시 주의사항 제공

APE 마스터 프롬프트 템플릿

## 역할
당신은 프롬프트 엔지니어링 전문가입니다.
주어진 작업에 대해 최적의 프롬프트를 자동으로 생성·평가·개선합니다.

## APE 실행 순서
Step 1: 아래 전략으로 후보 프롬프트 10개 생성
→ 역할 부여형 / 단계별 지시형 / 예시 포함형 / 제약 명시형 / 목적 중심형
→ 독자 설정형 / 형식 지정형 / 품질 기준형 / 역방향형 / 메타 지시형

Step 2: 각 후보를 100점 만점으로 평가
→ 명확성(25) · 완전성(25) · 실행 가능성(25) · 품질 유도력(25)

Step 3: 상위 3개 선택 → 교차 최적화 → 최종 1개 생성

Step 4: 최적 프롬프트 전문 + 선택 이유 + 주의사항 출력

## 작업 입력
작업: {자동화하고 싶은 작업 설명}
원하는 결과물: {어떤 결과물이 좋은 결과물인지}
피해야 할 것: {어떤 결과물이 나쁜 결과물인지}

실전 예시 — 고객 클레임 이메일 답장

## 작업 입력
작업: 고객 클레임 이메일 답장 작성
원하는 결과물: 고객이 화가 풀리고 우리 회사를 신뢰하게 하는 답장
피해야 할 것: 방어적 태도, 책임 회피, 공허한 사과

코딩 특화 APE — 평가 기준

## 코딩 프롬프트 품질 기준 (100점)
실행 가능성 (30): 코드가 바로 실행되는가?
완전성 (25): 엣지 케이스, 에러 처리 포함하는가?
가독성 (25): 주석과 변수명이 이해하기 쉬운가?
확장성 (20): 나중에 수정하기 쉬운 구조인가?

## 코딩 APE 입력 형식
작업: {무엇을 만들 것인가}
언어/프레임워크: {Python / JavaScript / etc.}
제약: {성능 요구, 라이브러리 제한 등}
경험 수준: {초보 / 중급 / 고급}

열쇠 1

명확하고 구체적으로

모호한 요청 대신 목표·수치·조건을 명시합니다.

마케팅 좀 알려줘

열쇠 2

CONTEXT — 충분한 배경 제공

목적지까지 가는 상세 내비게이션을 찍어주는 과정입니다.

은퇴 준비 글 써줘
나는 10년차 재무 상담사야. 불안해하는 50대 직장인에게 따뜻한 조언으로 써줘
열쇠 3

말보다 샘플 하나

원하는 결과물의 예시를 직접 보여주는 것이 가장 효과적입니다.

감동적인 이메일 써줘
내가 쓴 이 예시와 비슷한 톤으로 고객 감사 메일 써줘 (예시 첨부)
열쇠 4

거대한 업무 잘게 쪼개기

기획→카테고리 선정→상세 내용 작성 순으로 단계별로 질문합니다.

사업계획서 한 번에 짜줘
먼저 핵심 컨셉 3개만 제안해줘. 그 중 하나로 상세 목차 짜보자
열쇠 5

AI를 파트너로 대하기

완성본이 아니라 "초안"을 요청하고 반복적으로 개선합니다.

완벽한 보고서 써줘

RISEN 프레임워크

BaB 프레임워크

Before · After · Bridge. 수출 성공 스토리, 변화를 강조하는 사례 기반 콘텐츠 작성에 효과적인 스토리텔링 구조.

ROSES 실전 예시 — 가격 협상 전략

Role: 국제 무역 협상 전문가
Objective: FOB $50/unit 달성
Scenario:
- 바이어 첫 제시가: $40 · 우리 희망가: $50 · 시장 평균: $45
- 바이어 연간 예상물량: 50,000 units · 경쟁사(중국) 제시가: $42
Expected Solution: 협상 전략 3단계 + 단계별 가격·조건 + 양보 vs 가치 밸런스
Steps:
1. 현재 상황 분석
2. 가치 제안 준비 (품질, 납기, 인증)
3. 1차: 품질 차별화 강조 → $55 제시
4. 2차: 물량 증가 시 단계별 할인 ($55→$53→$50)
5. 계약서 작성 및 후속 조치
